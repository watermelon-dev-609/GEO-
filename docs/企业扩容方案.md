# GEO系统企业扩容迭代方案

## 版本路线图

```
v1.0 Personal（当前版本）
    ↓
v1.5 Team（团队协作版）
    ↓
v2.0 Enterprise（企业商用版）
    ↓
v3.0 Platform（SaaS平台版）
```

---

## 一、架构扩容路径

### 当前（v1.0 Personal）

| 维度 | 方案 |
|------|------|
| 后端 | FastAPI 单进程，本地启动 |
| 前端 | Vue 3 SPA，Vite 开发服务器 |
| 存储 | 本地文件系统（YAML + JSON + Pickle） |
| LLM | 适配器直连，用户自配Key |
| 向量 | sentence-transformers 本地加载，FAISS 文件索引 |
| 部署 | 手动启动，单机运行 |

### 升级到 v1.5 Team（预计改造量：15-20人天）

| 维度 | 变更 |
|------|------|
| **多用户** | 新增用户认证模块（JWT + bcrypt），SQLite 存储用户信息 |
| **权限** | 管理员/编辑/查看三级角色，API 中间件鉴权 |
| **项目共享** | 同团队用户可见共享项目，项目归属标记 |
| **操作日志** | 记录操作时间线，支持审计回溯 |

新增依赖：`python-jose[cryptography]` `passlib[bcrypt]` `sqlite-utils`

新增文件：
```
backend/app/
├── auth/          # 认证模块
│   ├── jwt.py     # JWT签发/验证
│   └── users.py   # 用户CRUD
├── models/user.py # 用户模型
└── middleware/auth.py # 鉴权中间件
```

### 升级到 v2.0 Enterprise（预计改造量：40-50人天）

| 维度 | 变更 |
|------|------|
| **数据库** | SQLite → PostgreSQL，Docker Compose 部署 |
| **ORM** | 引入 SQLAlchemy + Alembic 迁移管理 |
| **任务队列** | 引入 Celery + Redis，支持批量异步任务 |
| **文件存储** | 本地 → MinIO/阿里云OSS，支持大规模文件管理 |
| **API网关** | 引入 Nginx 反向代理，支持 HTTPS、限流 |
| **监控** | Prometheus + Grafana，接口性能监控 |
| **前端** | Docker 构建，Nginx 静态部署 |

新增依赖：`sqlalchemy` `alembic` `celery` `redis` `minio`

目录变更：
```
backend/
├── migrations/     # Alembic迁移文件
├── tasks/          # Celery异步任务
├── docker-compose.yml
└── Dockerfile

frontend/
├── Dockerfile
└── nginx.conf
```

### 升级到 v3.0 Platform（预计改造量：80-100人天）

| 维度 | 变更 |
|------|------|
| **多租户** | 租户隔离、独立配置、数据隔离 |
| **微服务** | 清洗/优化/评测/报表 拆分为独立服务 |
| **消息队列** | RabbitMQ/Kafka 服务间异步通信 |
| **K8s** | Kubernetes 集群调度、自动伸缩 |
| **计量计费** | API调用量统计、套餐管理 |
| **开放API** | RESTful API + API Key管理，支持第三方集成 |
| **管理后台** | 独立运营管理端 |

## 三、技术债务清理计划

| 项目 | 当前状态 | 目标状态 | 优先级 |
|------|---------|---------|--------|
| 类型注解 | 部分缺失 | 完整 mypy strict | 低 |
| 单元测试 | 无 | 覆盖率 > 80% | 中 |
| 错误处理 | 基础 HTTPException | 统一错误码+国际化 | 中 |
| 日志系统 | print + logging | 结构化日志 + ELK | 低 |
| 配置管理 | YAML文件 | 环境变量 + 配置中心 | 中 |
| API版本控制 | 无 | /api/v1/ 前缀 | 低 |

## 四、成本估算参考

### 当前版本（v1.0）
- 服务器：无（本地运行）
- API费用：仅LLM调用费用，按量付费
  - DeepSeek: ~0.5元/百万token
  - 通义千问: ~2元/百万token
  - GPT-4o: ~15元/百万token

### 企业版（v2.0）
- 云服务器：约 200-500元/月（4核8G起步）
- 数据库：约 100-300元/月（云数据库）
- 对象存储：约 10-50元/月
- 域名 + SSL：约 100-500元/年

### 平台版（v3.0）
- K8s集群：约 1000-3000元/月
- 消息队列：约 200-500元/月
- 监控系统：约 100-300元/月
- 总运营成本：约 2000-5000元/月

## 五、推荐扩容节奏

1. **第1-3个月**：使用 v1.0 个人版，熟悉流程，积累优化经验
2. **第3-6个月**：评估是否需要团队协作功能，按需升级到 v1.5
3. **第6-12个月**：如果业务量增长明显（月均100+篇文案），升级到 v2.0
4. **1年后**：评估是否对外提供GEO优化服务，考虑 v3.0 平台化
