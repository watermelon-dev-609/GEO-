# GEO系统企业扩容迭代方案

## 版本路线图

```
v1.0 Personal（✅ 已完成）
    ↓
v2.0 Personal（✅ 已完成 — 批量/安全/自动化/增强/体验）
    ↓
v2.5 Team（🔄 规划中 — 团队协作版）
    ↓
v3.0 Enterprise（📋 企业商用版）
    ↓
v4.0 Platform（📋 SaaS平台版）
```

## 一、当前版本（v2.0 Personal）架构总览

| 维度 | 方案 |
|------|------|
| 后端 | FastAPI 单进程，19 个路由模块，4 个 startup 事件 |
| 前端 | Vue 3 (Composition API) + Vite 6 + Element Plus + Pinia，14 页面 |
| 存储 | 纯 JSON 文件系统（YAML + JSON），零数据库依赖 |
| LLM | 适配器工厂模式，9 云平台 + 2 本地平台（Ollama / LM Studio） |
| 向量 | sentence-transformers 本地加载（bge-large-zh），FAISS 文件索引 |
| 任务调度 | APScheduler，定时任务持久化至 JSON 文件 |
| 安全 | JWT 密码鉴权（3 级角色）、API Key 格式校验 + 原子写入、审计日志（纯 ASGI） |
| 合规 | 50+ 禁词检测、免责声明、用量配额告警 |
| 部署 | 手动启动，单机运行，Windows 11 / Linux 兼容 |

## 二、架构扩容路径

### 升级到 v2.5 Team（预计改造量：15-20 人天）

| 维度 | 变更 |
|------|------|
| **多用户** | 用户注册/登录模块增强（JWT + bcrypt），SQLite 存储用户信息 |
| **权限** | 管理员/编辑/查看三级角色，API 中间件鉴权细化 |
| **项目共享** | 同团队用户可见共享项目，项目归属标记 |
| **操作日志** | 结构化操作时间线，支持审计回溯 |
| **协作通知** | 站内消息、邮件通知 |

> 注：当前 v2.0 已有基础鉴权和审计日志，v2.5 重点是多用户协作场景的完善。

新增依赖：`python-jose[cryptography]` `passlib[bcrypt]`（部分已有）`sqlite-utils`

新增文件：
```
backend/app/
├── auth/              # 认证模块增强
│   ├── jwt.py         # JWT 签发/验证（已有基础）
│   ├── users.py       # 用户 CRUD
│   └── permissions.py # 细粒度权限控制
├── models/user.py     # 用户模型
└── middleware/auth.py  # 鉴权中间件增强
```

### 升级到 v3.0 Enterprise（预计改造量：40-50 人天）

| 维度 | 变更 |
|------|------|
| **数据库** | JSON 文件 → PostgreSQL，Docker Compose 一键部署 |
| **ORM** | 引入 SQLAlchemy + Alembic 迁移管理 |
| **任务队列** | 引入 Celery + Redis，支持大规模批量异步任务 |
| **文件存储** | 本地 → MinIO / 阿里云 OSS，支持大规模文件管理 |
| **API 网关** | 引入 Nginx 反向代理，支持 HTTPS、限流 |
| **监控** | Prometheus + Grafana，接口性能监控面板 |
| **前端部署** | Docker 构建，Nginx 静态部署 |
| **CI/CD** | GitHub Actions / GitLab CI，自动化测试 + 部署 |

新增依赖：`sqlalchemy` `alembic` `celery` `redis` `minio`

目录变更：
```
backend/
├── migrations/         # Alembic 迁移文件
├── tasks/              # Celery 异步任务
├── docker-compose.yml
├── Dockerfile
└── alembic.ini

frontend/
├── Dockerfile
└── nginx.conf
```

### 升级到 v4.0 Platform（预计改造量：80-100 人天）

| 维度 | 变更 |
|------|------|
| **多租户** | 租户隔离、独立配置、数据隔离 |
| **微服务** | 清洗/优化/评测/报表 拆分为独立服务 |
| **消息队列** | RabbitMQ / Kafka 服务间异步通信 |
| **K8s** | Kubernetes 集群调度、自动伸缩 |
| **计量计费** | API 调用量统计、套餐管理、支付集成 |
| **开放 API** | RESTful API + API Key 管理，支持第三方集成 |
| **管理后台** | 独立运营管理端 |
| **白标** | 支持客户自定义品牌标识和域名 |

## 四、技术债务清理计划

| 项目 | 当前状态 | 目标状态 | 优先级 |
|------|---------|---------|--------|
| 并发安全 | sessions dict / JSON 写入无锁 | 引入 `asyncio.Lock` 或文件锁 | 🔴 P0 |
| CSV 导出 | 逗号转义未处理 | 正确 RFC 4180 转义 | 🔴 P0 |
| Analytics 参数 | days 参数未生效 | 修复参数传递链路 | 🔴 P0 |
| Claude 适配器 | 适配器存在但 AIPlatform 无条目 | 添加 Claude 到枚举 | 🟡 P1 |
| 竞品/关键词端点 | 引擎已就绪但 API 端点未暴露 | 暴露 deconstruct / exposure-words / effectiveness 端点 | 🟡 P1 |
| 五维信息 | 硬编码在 5+ 文件中 | 提取到共享配置 `dimensions_shared.py` | 🟡 P1 |
| 前端常量 | SANDTABLE_TYPES 等 4 文件重复 | 提取到共享常量文件 | 🟡 P1 |
| APScheduler | 绑定单事件循环 | 多进程调度器支持 | 🟢 P2 |
| 类型注解 | 部分缺失 | 完整 mypy strict | 🟢 P2 |
| 单元测试 | 无 | 覆盖率 > 80% | 🟡 P1 |
| 错误处理 | 基础 HTTPException | 统一错误码 + 国际化（19 错误码已完成） | 🟢 P2 |
| 日志系统 | logging + 文件日志 | 结构化日志 + ELK | 🟢 P2 |
| 配置管理 | YAML 文件 + .env | 环境变量 + 配置中心 | 🟢 P2 |
| API 版本控制 | 无 | /api/v1/ 前缀 | 🟢 P2 |
| 评测校准 | temperature=0.3 未完成 | 完成多温度校准测试 | 🟡 P1 |

## 五、成本估算参考

### 当前版本（v2.0 Personal）
- 服务器：无（本地运行）
- API 费用：仅 LLM 调用费用，按量付费
  - DeepSeek：~0.5 元/百万 token
  - 通义千问：~2 元/百万 token
  - 豆包 / Kimi / 元宝 / 星火：~1-2 元/百万 token
  - GPT-4o：~15 元/百万 token
  - Claude API：~10-15 元/百万 token
- 本地 LLM（Ollama / LM Studio）：**完全免费**，无 API 费用

### 团队版（v2.5）
- 云服务器：约 100-200 元/月（2 核 4G 轻量云服务器）
- 数据库：SQLite 无需额外费用
- 域名 + SSL：约 100-500 元/年（可选）

### 企业版（v3.0）
- 云服务器：约 200-500 元/月（4 核 8G 起步）
- 云数据库（PostgreSQL）：约 100-300 元/月
- 对象存储（OSS）：约 10-50 元/月
- Redis：约 50-150 元/月
- 域名 + SSL：约 100-500 元/年
- 合计：约 500-1,500 元/月

### 平台版（v4.0）
- K8s 集群：约 1,000-3,000 元/月
- 消息队列：约 200-500 元/月
- 监控系统：约 100-300 元/月
- 数据库集群：约 500-1,000 元/月
- 总运营成本：约 2,000-5,000 元/月
- 可通过多租户分摊，单客户成本可控

## 六、推荐扩容节奏

| 阶段 | 时间 | 动作 |
|------|------|------|
| **当前** | — | 使用 v2.0 全部功能，覆盖批量处理、安全合规、自动化、版本管理 |
| **第 1-3 个月** | 2026 Q3 | 修复 P0 技术债（并发安全 / CSV 转义 / Analytics），暴露竞品/关键词端点 |
| **第 3-6 个月** | 2026 Q3-Q4 | 评估团队协作需求，按需升级到 v2.5，添加多用户和项目共享 |
| **第 6-12 个月** | 2026 Q4-2027 Q1 | 如果业务量增长明显（月均 100+ 篇文案），升级到 v3.0 企业版 |
| **1 年后** | 2027+ | 评估是否对外提供 GEO 优化 SaaS 服务，考虑 v4.0 平台化 |
